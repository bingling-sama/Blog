# 外链文章（推荐阅读）Spec

- 状态：已按默认决策实现
- 日期：2026-11-13
- 范围：现有博客的外链文章支持
- 本文定义需求与实现边界；使用说明与回归命令见 `docs/external-link-posts.md`。

## 1. 背景与目标

博客作者希望分享别人写的文章：分享记录出现在现有文章列表中，读者点击标题直接访问原文，而不必先进入本站文章页。

采用现有 Markdown 文章机制，增加可选外链字段。不另建收藏系统、不要求迁移已有文章。

目标：

1. 发布一条推荐只需创建一个 Markdown 文件并填写元数据。
2. 首页、归档、分类和标签等文章列表行为一致。
3. 明确区分外部推荐与本站原创，保留署名与推荐语。
4. 保留可访问的站内记录页，兼容已有站内链接及订阅入口。

不在本期范围：抓取原文、转载全文、自动获取标题或封面、链接可用性巡检、点击统计、独立推荐频道、批量导入。

## 2. 核心决策

以下默认值已随“直接按 spec 完整实现”的要求确认为实现约定：

| 项目 | 决策 |
| --- | --- |
| 内容存储 | 继续使用 `blog/posts/**/*.md` |
| 类型判定 | 存在合法 `externalLink` 即为外链文章，不增加额外 `type` 字段 |
| 列表点击 | 直接访问原文，新标签页打开 |
| 站内页面 | 保留推荐记录页，不自动重定向 |
| 排序 | 按推荐记录的 `date` 与普通文章混排 |
| 分类、标签与计数 | 参与现有分类、标签、归档、分页与文章总数统计 |
| 字数与阅读时长 | 外链文章不计算、不展示 |
| RSS | 保留站内记录作为条目身份，条目主链接指向原文 |
| Telegram 通知 | 指向站内记录页，明确标注推荐与原文来源 |

## 3. 作者使用方式

例如新建 `blog/posts/development/recommend-example.md`：

```markdown
---
title: 一篇值得读的文章
date: 2026-11-13 12:00:00
description: 作者把这个问题讲得很透彻，尤其推荐其中的案例分析。
category: Development
tags:
  - 推荐阅读
externalLink: https://example.com/article
sourceAuthor: 原作者
---
```

正文允许为空。需要补充长推荐语时，可以在正文中写自己的评论，但不自动复制原文。`description` 负责列表摘要，正文负责站内记录页的补充内容。

`推荐阅读` 标签由作者自行添加，不作为识别外链文章的依据，也不自动写入标签集合。

## 4. 数据契约与校验

### 4.1 Frontmatter

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `title` | string | 必填，非空，推荐使用原文标题；展示时不强制修改 |
| `date` | 现有日期格式 | 必填，表示推荐发布时间，不表示原文发布日期 |
| `description` | string | 外链文章必填，非空，为本站作者自己的推荐语 |
| `category` | string | 沿用现有分类约定 |
| `tags` | string[] | 沿用现有标签约定 |
| `externalLink` | string | 新增；缺省表示普通文章，存在则必须是合法外链 |
| `sourceAuthor` | string | 新增、可选；去除首尾空白，空字符串视为未提供 |

外链校验规则：

- 去除首尾空白后解析为绝对 URL。
- 仅允许 `https:`、`http:`，且必须包含主机名。
- 拒绝相对路径、协议相对地址、`javascript:`、`data:`、`file:` 及带用户名或密码的 URL。
- 拒绝地址内部的未编码空格及控制字符，避免 URL 解析器自动清理后与保存值不一致。
- `externalLink` 显式为空、类型错误或格式非法时，构建失败，错误包含文件路径及字段名；不得静默降级为普通文章。
- 不发送网络请求验证可达性，不修改查询参数与 hash。
- 普通文章不因这次功能而新增元数据校验要求。

### 4.2 内部文章模型

在现有 `Post` 上增加可选 `externalLink?: string`、`sourceAuthor?: string`。

**`Post.url` 始终保留站内文章地址**，不能直接用原文 URL 替换。它用于站内路由匹配、记录页以及稳定身份。

所有列表使用同一链接解析规则：

- 普通文章：`href = withBase(post.url)`，保持现有打开方式。
- 外链文章：`href = post.externalLink`，不拼接本站 base。
- 外链文章使用 `target="_blank"`、`rel="noopener noreferrer"`。
- 外链文章的 `readingTime`、`wordCount` 不赋值，而非设为零。

链接协议校验必须覆盖构建与通知链路，避免各入口出现不同的安全规则。

## 5. 页面行为

### 5.1 所有文章列表

覆盖首页列表，以及归档、标签、分类等使用文章数据的入口；实施前检查全部 `Post.url` 消费者，不仅修改首页。

- 标题为真实 `<a>`，不依赖 JavaScript 点击跳转，支持键盘、复制链接与浏览器菜单。
- 外链文章显示「推荐阅读」标识及外链图标，不要求在标题文本中添加前缀。
- 提供“将在新标签页打开”的可访问提示，装饰性图标不重复朗读。
- 首页摘要使用 `description`；有 `sourceAuthor` 时展示“原作者：姓名”。紧凑列表可省略署名，但不得省略推荐标识。
- 标签仍跳转本站标签页，不被外链标题的点击区域覆盖。
- 不展示外链文章的字数与阅读时长，不推测原文长度。
- 手机窄屏及深浅主题下标识可辨认，不遮挡日期或破坏标题链接。
- 本期不增加筛选器，不调整现有分页大小。

### 5.2 站内推荐记录页

直接访问对应站内 URL 时，即使 Markdown 正文为空，也必须展示：

1. 标题与「推荐阅读」标识。
2. 推荐日期、推荐语。
3. 原作者（填写时）与来源主机名（从 URL 解析）。
4. “阅读原文”链接，打开行为与列表一致。
5. “本文为外部文章推荐，原文版权归原作者所有”的说明。
6. Markdown 正文中的补充评论（存在时）。

标题、推荐语与来源区由模板提供，无需作者重复手写。保持现有布局结构，避免出现重复 H1。来源字段按文本渲染，不作为任意 HTML 注入。

不自动跳转，不嵌入原网站。记录页不展示阅读时长；如保留本站页面访问统计，应标为“本页访问量”，不得暗示其代表原文阅读量。站点页脚的 MIT 声明不应被解释为授予外部原文许可，记录页必须明确版权边界。

### 5.3 搜索与收录

- 保留站内记录页及其稳定地址，若现有搜索或 sitemap 收录该页，则继续沿用。
- 不把外部原文 URL 当作本站页面写入 sitemap。
- 本期不新增或改造搜索系统，不抓取外部正文参与索引。

## 6. RSS 与 Telegram

### 6.1 RSS

普通文章条目保持现状。外链文章：

- 标题在订阅展示层加“[推荐阅读] ”，不修改原始 `title`。
- 条目主链接指向合法的 `externalLink`。
- GUID 使用绝对站内记录页 URL，明确为非永久链接身份；修改原文链接不得创建新的条目身份。
- 摘要或内容包含推荐语、原作者（填写时）、原文链接及站内记录页链接。
- 署名文案明确区分“本站推荐者”和“原作者”，不能让默认站点作者被误认为原文作者。
- 不输出抓取的原文全文，RSS 文本及 URL 必须正确转义。

现有 RSS 配置在 `.vitepress/config.mts`，使用 `vitepress-plugin-rss`。实现前核实当前版本的条目转换能力，不假定现有 `filter` 回调能完成上述改写。若插件扩展点不足，先提出最小替代方案再实施，不在本 spec 中预设未经核实的 API。

### 6.2 Telegram 通知

现有 `scripts/notify-teleblog.mjs` 使用站内 URL 发送通知。本期保留这一行为，减少外部服务去重与更新语义变化：

- 通知标题加“[推荐阅读] ”。
- 简介包含推荐语、原作者（填写时）以及原文 URL。
- 主链接仍为站内记录页，读者可从记录页打开原文。
- 不增加 teleblog-api payload 字段，不修改对方服务接口。
- 保留现有草稿跳过行为，不借本功能重构整个草稿机制。
- 外链校验失败时该记录不得发送；必须返回可定位的错误。
- 验证仅使用 dry-run，不发送真实通知。

## 7. 实现边界与落点

| 位置 | 预期变更 |
| --- | --- |
| `theme/scripts/functions.ts` | 扩展 `Post` 字段；必要时提供共享链接解析规则 |
| `theme/scripts/posts.data.ts` | 读取、校验外链元数据，保留站内 URL，跳过外链阅读时长计算 |
| `theme/components/Posts.vue` | 首页跳转规则、推荐标识、来源署名 |
| `theme/components/PostItem.vue` | 紧凑列表的外链支持；同步调整其调用者传参 |
| `theme/components/MyLayout.vue` | 站内兜底内容、外链阅读时长与访问统计文案处理 |
| `.vitepress/config.mts` | RSS 条目适配，保留普通文章逻辑 |
| `scripts/notify-teleblog.mjs` | 推荐通知文案、来源与校验 |

实现以现有组件和样式为基础；只在减少重复规则时抽取小工具，不新增内容数据库、服务端跳转服务或通用内容管理框架。

建议分三步交付：

1. 数据契约、校验与全部列表入口。
2. 站内记录页及署名、版权边界。
3. RSS、通知与回归测试。

三个步骤全部完成才视为本功能交付，不将订阅支持留作隐含待办。

## 8. 验收标准

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| A1 | 现有文章没有 `externalLink` | 列表、站内跳转、阅读时长、RSS 与通知行为不变 |
| A2 | 新增合法外链文章 | 出现在按日期排序后的列表、对应分类、标签与归档中，计数及分页正确 |
| A3 | 点击任一文章列表中的外链标题 | 直接在新标签页访问原文，无本站 base 前缀，含安全 rel 属性 |
| A4 | 点击外链文章标签 | 正常进入本站标签页，不跳往原文 |
| A5 | 正文为空，直接访问站内记录页 | 有标题、日期、推荐语、来源、原文入口与版权说明，无空白主体或自动重定向 |
| A6 | 有正文或无 `sourceAuthor` | 补充评论正常显示；未填作者不产生空署名或虚构作者 |
| A7 | 任意外链文章 | 列表和记录页均无字数、阅读时长；本站访问量不被标作原文阅读量 |
| A8 | 非法协议、相对地址、空值、非字符串、带凭据 URL | 构建失败且指出文件与字段；通知不得发送该条记录 |
| A9 | 外链含查询参数、hash 或首尾空白 | 清理首尾空白后可正常打开，参数与 hash 保留 |
| A10 | RSS 外链条目 | 主链接为原文，GUID 为稳定站内身份，推荐语与署名明确，无虚假的原文作者归属 |
| A11 | 修改同一记录的原文 URL | 站内路径与 RSS GUID 不变 |
| A12 | 通知 dry-run | 主链接为站内记录，标题带推荐前缀，简介含原作者（如有）及原文 URL，无真实请求 |
| A13 | 键盘、窄屏与深浅主题 | 链接可聚焦、可激活，新标签页提示可感知，标识无明显遮挡或溢出 |
| A14 | 非根路径 base 的测试构建 | 普通文章正确带 base，原文外链不带 base |

验证至少包括：元数据及链接解析的自动化用例、生产构建（`pnpm build`）、生成 RSS 的 XML 检查、通知 dry-run、全部列表入口与站内记录页的浏览器回归。不以构建成功替代行为验证；测试文章应使用临时夹具，不随交付发布虚构推荐。

## 9. 决策确认

1. 是否接受所有外链默认新标签页打开？本草案默认接受。
2. 是否接受外链记录计入现有文章总数？本草案默认计入，不单列原创数量。
3. 是否接受 Telegram 主链接保留站内记录页、而列表和 RSS 主链接直达原文？本草案默认接受，以保持通知链路兼容。

以上默认决策均已采用；如修改，应同步更新相应验收标准。

## 10. 实现补充

- 站内记录的标题与来源区由 `.vitepress/plugins/external-posts.ts` 注入 Markdown 渲染流程，`ExternalPostRecord.vue` 展示元数据；已有同名 H1 去重，其他正文 H1 降为 H2。
- `.vitepress/config.mts` 对页面元数据执行共享校验，列表加载器和通知也使用相同规则。
- 本地搜索的 HTML 渲染仅对推荐记录将来源组件占位替换为转义后的推荐语，使无正文记录也能被现有搜索索引；搜索结果保留站内记录入口。
- RSS 插件 0.4.4 固定拼接本站域名，不能直接生成外链主链接。`scripts/recommendation-rss.mjs` 包装其生成钩子，等待原 feed 写入后通过 XML DOM 仅改写推荐条目；普通条目的内容与语义保留。
- 通知 YAML 解析改用仓库已有的 `gray-matter`，以统一多行推荐语及字段类型；对应 GitHub Actions 增加锁定依赖安装步骤。
- 自动化测试入口为 `pnpm test` 与 `pnpm test:external-posts`。后者覆盖真实生产输出和浏览器行为，不使用真实通知服务。
